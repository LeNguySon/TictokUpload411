# Instinct 011: Video Scheduling Persistence & Real-time Auto-Dispatch Pipeline

## Context & Problem
In high-throughput multi-account TikTok automation, video upload schedules generated by `ScheduleVideoDialog` previously resided solely in transient GUI table cells (`video_table.setItem(...)`). Any application restart, profile switch, or table reload caused all scheduled slots to be lost. Furthermore, `video_registry` lacked a dedicated `schedule_time` column, and there was no proactive scheduler to dispatch videos when their designated publication time arrived.

## Engineering Solution
1. **Database Schema & Pre-Migration**:
   - Added `schedule_time TEXT DEFAULT NULL` to `video_registry` with a composite index `idx_video_registry_schedule ON video_registry(status, schedule_time);`.
   - In `runner.py`, executed PRAGMA checks and pre-migration `ALTER TABLE video_registry ADD COLUMN schedule_time` before index creation to prevent `sqlite3.OperationalError: no such column: schedule_time` on existing databases.
2. **Repository Capabilities**:
   - `VideoRepository.update_schedule(video_id, schedule_time, assigned_profile_id)`: Atomically updates video schedule and profile targets.
   - `VideoRepository.batch_update_schedules(items)`: Batch updates multiple video slots in a single atomic transaction.
   - `VideoRepository.list_scheduled_due(max_time_iso)`: High-performance query returning all available videos where `schedule_time <= current_time`, sorted by schedule time.
   - `VideoRepository.list_available()`: Joins with `profiles` to seamlessly provide `assigned_profile_name` for UI rendering.
3. **Presentation & Real-Time Auto-Dispatch**:
   - `VideoQueueTableWidget`: Updated `load_videos` to read `v.get("schedule_time") or v.get("schedule")` into Column 6, and display assigned profile name or ID into Column 7.
   - `TikTokManagerMainWindow._on_schedule_videos` and `_on_schedule_videos_from_table`: Wire `ScheduleVideoDialog` directly into `video_repo.update_schedule()` and refresh table.
   - `TikTokManagerMainWindow.scheduler_timer`: A 15-second non-blocking `QTimer` scanning `video_repo.list_scheduled_due()`, reserving due videos atomically (`try_reserve`), and dispatching `UploadWorker` tasks onto `QThreadPool`.
